# 数织每日一题

入口：数织随机模式右上角的“每日一题”，地址 `/nonogram/daily`。

- 北京时间每天 0 点更新日期，每天仅两题：困难 15×15、极难 10×10。
- 后端启动后台线程，立即补齐当天与次日题目，完整时每 60 秒检查一次，失败时每 10 秒重试。所有玩家读取同一份已发布题目；极难生成失败不会降级为简单题。
- 玩家接口只读数据，不生成、不等待生成锁。首次启动空题库时入口显示“题库准备中”，每 10 秒检查就绪状态后自动开放。服务停机期间不能生成，恢复运行后补齐；正常运行时午夜直接切换到提前准备好的题目。
- 发布的题目持久化保存；同一天重启或重新部署不会主动换题。不能删除题库数据，否则题目可能重新生成。
- 玩家进度、颜色、用时及完成状态按题目分别保存在当前浏览器的 localStorage 中，与随机模式分开。不支持跨设备同步；清理浏览器数据会丢失进度。
- 切换题目、离开页面或切入后台时暂停计时。跨过午夜时，当前打开的昨日题目可以继续完成，上方选择区更新为今日题目。重新进入页面默认选择今日题目。

## 部署

本功能同时修改前端和后端，两端都需要部署并重启后端。没有新增 npm 或 Python 依赖，不必仅为本次改动运行 `npm ci`。后台预生成随正常后端启动，无须额外配置定时任务。

首次部署可在相同的后端环境与 `backend` 目录先执行 `python -m app.modules.nonogram_daily.worker`，补齐当天和次日题库后再开放前端。退出码 0 表示全部就绪；退出码 1 表示有题生成失败，可再次运行，已发布题目不会重新生成。

生产环境沿用现有 `GAME_REPO=redis` 与 `REDIS_URL` 配置。每日题目使用 `mh:nonogram-daily:v1:日期:尺寸:难度` 键，首次发布使用 Redis `SET NX`，保证并发请求返回同一个题目。键不设置过期时间；Redis 数据应开启可靠持久化并备份，避免清空/淘汰这些键。

本地开发或 `GAME_REPO=memory` 时，每日题目单独使用 SQLite，默认文件为 `backend/data/nonogram-daily.sqlite3`，不随 Git 提交。可用环境变量 `NONOGRAM_DAILY_DB_PATH` 指定绝对路径。如果生产环境也使用 SQLite，请将路径放在代码发布目录以外，并保证运行后端的用户有读写权限，以免文件同步（尤其 `rsync --delete`）删除题库。

新增接口均在现有 `/api/` 代理下，无须为它们单独配置 Nginx：

- `GET /api/nonogram-daily/catalog`：今日日期、更新时间、两个题目标识及 `ready` 状态。
- `GET /api/nonogram-daily/puzzle?date=YYYY-MM-DD&size=15&difficulty=hard`：只读今日题目。缺题立即返回 503 与 Retry-After，不触发生成；非法组合或非今日日期返回 409。

## 验证

在后端 Python 环境、`backend` 目录执行：

```text
python -m unittest discover -s tests -p test_nonogram_daily.py -v
```

覆盖北京时间午夜、两种固定组合、后台预生成与失败重试、生命周期启动停止、只读请求、持久化、并发首次发布、Redis 发布约束及 HTTP 参数校验。
